# 🔥 **Basic & Essential HTTP Status Codes for Web Pentesting**

These are the codes you **must know** while doing recon, fuzzing, directory brute force, or API testing.

---

## ✅ **1xx – Informational**

| Code             | Meaning                 | Pentest Use                      |
| ---------------- | ----------------------- | -------------------------------- |
| **100 Continue** | Server accepted headers | Rare, mostly seen in API fuzzing |

---

## ✅ **2xx – Success Codes**

| Code               | Meaning             | Pentest Use                                      |
| ------------------ | ------------------- | ------------------------------------------------ |
| **200 OK**         | Request successful  | The page/resource exists → recon/data extraction |
| **201 Created**    | Resource created    | Identify misconfigured APIs                      |
| **202 Accepted**   | Request queued      | Used in asynchronous APIs                        |
| **204 No Content** | No body in response | Often seen in DELETE/PUT APIs                    |

---

## ✅ **3xx – Redirection Codes**

| Code                      | Meaning                            | Pentest Use                                     |
| ------------------------- | ---------------------------------- | ----------------------------------------------- |
| **301 Moved Permanently** | Permanent redirect                 | Used to find hidden paths or old endpoints      |
| **302 Found**             | Temporary redirect                 | Often used in login flows → useful for bypasses |
| **303 See Other**         | Redirect with GET                  | Can help detect server-side auth flow           |
| **307 / 308 Redirect**    | Strict redirect (method preserved) | Watch for authentication / method bypass tricks |

---

## ✅ **4xx – Client Error Codes (VERY IMPORTANT)**

These codes are heavily used in **fuzzing, directory enumeration, auth bypass, IDOR, testing rate limits**, etc.

| Code                           | Meaning              | Pentest Use                                           |
| ------------------------------ | -------------------- | ----------------------------------------------------- |
| **400 Bad Request**            | Invalid input        | Helps identify input validation flaws                 |
| **401 Unauthorized**           | Auth required        | Check for **auth bypass / token manipulation**        |
| **403 Forbidden**              | Access denied        | Test for **403 bypasses** (very common)               |
| **404 Not Found**              | Resource not found   | Helps detect **hidden endpoints / directory fuzzing** |
| **405 Method Not Allowed**     | Incorrect method     | Used in **method tampering** tests (e.g., POST → PUT) |
| **408 Timeout**                | Server timeout       | Useful for **DoS, Slowloris** tests                   |
| **409 Conflict**               | Conflict in request  | Seen during registration brute force                  |
| **410 Gone**                   | Removed permanently  | Indicates old resources                               |
| **413 Payload Too Large**      | Request body too big | Useful for **file upload fuzzing**, DoS               |
| **415 Unsupported Media Type** | Wrong content type   | Important for **API testing**                         |
| **429 Too Many Requests**      | Rate limit hit       | Used for **rate-limit bypass** tests                  |

---

## ✅ **5xx – Server Error Codes (Pentest Gold)**

These often indicate **misconfigurations, vulnerabilities, weak input validation, potential RCE, SQLi, LFI**, etc.

| Code                               | Meaning                   | Pentest Use                                     |
| ---------------------------------- | ------------------------- | ----------------------------------------------- |
| **500 Internal Server Error**      | Server failed             | Great indicator of **SQLi, LFI/RFI, XXE, RCE**  |
| **501 Not Implemented**            | Not supported             | Rare, but indicates misconfig                   |
| **502 Bad Gateway**                | Invalid upstream response | Found during WAF bypass or load balancer issues |
| **503 Service Unavailable**        | Overloaded/down           | Useful in **DoS** testing                       |
| **504 Gateway Timeout**            | Upstream timeout          | Seen during **heavy payload fuzzing**           |
| **505 HTTP Version Not Supported** | Protocol version issue    | Rare; sometimes WAF-triggered                   |
